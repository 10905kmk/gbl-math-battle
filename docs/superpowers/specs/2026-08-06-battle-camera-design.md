# 대전 화면 카메라 — 플레이어 위치를 따라가는 뷰포트

## 배경

배틀로얄 맵이 실제 좀비고 이미지(2176x1632)로 교체되면서, 지금 `frontend/src/screens/battle.js`가 Konva `Stage`를 `DEFAULT_MAP.arenaSize`(월드 크기) 그대로 생성하고 있는 게 문제가 됐다 — 화면(`.battle-arena`)이 2176x1632 CSS 픽셀짜리 거대한 캔버스가 되어 실질적으로 플레이가 불가능하다. 화면에 보이는 영역(뷰포트)과 맵 전체 크기(월드)를 분리하고, 뷰포트가 참가자 자기 캐릭터를 따라다니는 카메라를 도입한다.

## 뷰포트/월드 분리

새 상수 `VIEWPORT_SIZE = { width: 800, height: 600 }`(고정) — Konva `Stage`를 이 크기로 생성한다(지금처럼 `DEFAULT_MAP.arenaSize`로 생성하지 않는다). 캐릭터/무기 아이콘/배경 이미지 등 기존 노드들은 지금처럼 월드 좌표(0~2176, 0~1632) 그대로 두고 위치를 계산한다 — 좌표 계산 로직 자체는 바뀌지 않는다.

카메라는 `Layer` 하나를 통째로 이동시켜 구현한다: 매 `battle:state` 갱신마다 내 캐릭터의 월드 좌표를 기준으로 카메라 오프셋(`cameraX, cameraY`)을 계산하고, `layer.x(-cameraX); layer.y(-cameraY);`를 적용한다. 노드 하나하나의 좌표를 다시 계산할 필요 없이, 레이어 전체가 화면 기준으로 밀리면서 카메라 효과가 난다.

## 카메라 계산

```
cameraX = clamp(myX - VIEWPORT_SIZE.width / 2, 0, max(0, worldWidth - VIEWPORT_SIZE.width))
cameraY = clamp(myY - VIEWPORT_SIZE.height / 2, 0, max(0, worldHeight - VIEWPORT_SIZE.height))
```

내 캐릭터가 화면 중앙(400, 300)에 오도록 카메라를 두되, 맵 가장자리 근처에서는 그 이상 못 밀리고 멈춘다(clamp). 하한/상한 계산에 `max(0, ...)`를 넣은 이유: 월드가 뷰포트보다 작아지는 경우(향후 맵이 작아지면)에도 `상한 < 0`이 되어 `clamp`가 이상하게 동작하는 걸 막기 위한 방어(지금 데이터로는 항상 월드가 훨씬 크므로 실질적으로는 발동하지 않지만, `weaponDamage` clamp 등 이 프로젝트 전반의 방어적 코딩 원칙을 따른다).

카메라는 보간(이징) 없이 서버 상태를 받을 때마다 즉시 그 위치로 이동한다 — 캐릭터 이동 자체도 지금 보간 없이 서버 틱을 그대로 반영하는 방식이라 일관성을 유지한다.

"내 캐릭터"가 없는 경우(아직 `battle:state`를 한 번도 못 받은 초기 렌더 등)는 카메라가 `(0, 0)`을 기준으로 시작한다.

## 마우스 조준 좌표 변환

`stage.getPointerPosition()`은 뷰포트(스테이지) 기준 좌표를 반환한다 — 뷰포트가 800x600으로 고정되면서 이 값의 범위도 0~800/0~600이 된다. 지금 조준 계산(`updateAimFromPointer`)은 이 값을 월드 좌표(`selfPosRef`)와 직접 빼고 있어서, 카메라가 도입되면 그 차이가 화면상 거리가 아니라 잘못된 값이 된다.

변환식: `월드좌표 = 뷰포트좌표 + 카메라오프셋`. 현재 카메라 오프셋을 별도 ref(예: `cameraRef`)에 저장해두고, `updateAimFromPointer`가 `pointer.x/y`에 그 오프셋을 더한 뒤 내 캐릭터의 월드 좌표와 빼서 조준 벡터를 계산하도록 바꾼다.

## CSS

`frontend/src/screens/battle.css`의 `.battle-arena`(Konva 캔버스를 감싸는 박스)와 `.battle-controls`(조작 UI)의 크기 기준이 지금은 `DEFAULT_MAP.arenaSize.width`(월드 너비, 2176)로 잡혀 있다 — 이제 뷰포트 너비(800, 고정 상수)로 바꾼다. 좁은 화면(부스 태블릿/폰)에서 줄어드는 반응형 로직(`min(뷰포트너비, 100vw - 3rem)`) 자체는 그대로 유지한다.

## 스코프 제외

- 카메라 줌(확대/축소) — 지금은 1:1 배율만 지원.
- 카메라 부드러운 보간(이징)/관성 — 서버 틱을 즉시 반영하는 지금 방식 유지.
- 다른 참가자 화면까지 신경 쓰는 로직 — 각 참가자가 자기 기기에서 각자 자기 캐릭터를 중심으로 화면을 보므로(관전 모드 없음), 참가자별 카메라 상태는 완전히 독립적이고 서버 조율이 필요 없다.
- 화면 밖 캐릭터/장애물에 대한 별도 컬링(성능 최적화) — 참가자 수가 최대 8명 수준이라 Konva의 기본 클리핑으로 충분하고, 별도 최적화는 이번 스코프가 아니다.

## 테스트 범위

카메라 계산은 프론트엔드 렌더링 로직이라 이 프로젝트의 기존 관례(Konva 렌더링 위주 컴포넌트는 자동화 테스트 없이 라이브 검증)를 따른다. `frontend/src/screens/battle.js`는 문법 검증(`node --check`) 후, Playwright로 실제 화면에서: (1) 캐릭터를 이동시키면 카메라가 따라오는지, (2) 맵 가장자리에서 카메라가 멈추고 그 너머 빈 공간이 안 보이는지, (3) 마우스 조준이 카메라가 이동한 상태에서도 정확한 방향으로 나가는지 확인한다.
